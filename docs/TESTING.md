# Testing

Three tiers, mirroring Gentle AI, plus a leak battery that runs on every tier.

## Tier 1 — unit (`go test ./...`, `pnpm test` in packages)

| Package | Must cover |
| --- | --- |
| `vault` | layer resolution (project overrides global, global fallback, outside a repo, worktrees, case-folded roots on Windows/macOS); `mv` keeps value and metadata; envelope round-trip; tag failure → `vault_corrupt`; rollback counter; atomic write survives SIGKILL mid-write (temp file left, target intact) |
| `keychain` | backend selection; passphrase mode KDF params; cached key TTL expiry |
| `grants` | (name, layer) binding: a global grant never injects a project override and the reverse; `mv`/`replace`/`rm` drop grants; each scope; expiry purge; `once` consumed exactly once; project root resolution incl. worktrees; no inheritance across sessions |
| `exec` | env scrubbing (same-named parent var removed); injection present in child, absent in parent after; dump-guard list (every entry, plus negative cases like `env | grep PATH` being *allowed* when no secret is injected); binary allowlist with wrappers (`sudo`, `npx`, `uv run`); timeout kills the process group; exit code passthrough |
| `redact` | raw, base64 std/url ±padding, percent (query/path/strict/Python `quote`/JS `encodeURIComponent`, either hex case), JSON-escaped (incl. `\/`), quoted; multi-line values (LF/CRLF translation, each line ≥ 16 bytes alone, whole PEM, interleaved with other output); base64 inner-substring at all three byte alignments (Basic auth `base64(user:value)`, 0–8 byte prefixes, ±padding, std/url); chunk boundaries at every offset of a value and one-byte writes; short-value warning and still redacted; overlapping values (longest wins), shared prefixes, adjacent occurrences; fail-closed after `Wipe`; never printed via `fmt`. `BenchmarkRedact` / `BenchmarkRedactStream` track 1 MiB against 16 secrets (about 130 MB/s on a Ryzen 7 7435HS) |
| `prompt` | each backend behind an interface with a fake; cancel/blank/whitespace paths; value never in argv or stdout; native backends: exact argv or script per helper and dialog kind, escaping tables (quotes, backslashes, `$`, backticks, `%`, newlines, NUL, ANSI, bidi, invalid UTF-8) proving request text cannot leave its literal, stdout parsing and cancel codes per tool, availability matrix and selection order through injected `GOOS`/env/`LookPath`, and (Windows) the real PowerShell parser over every script |
| `audit` | hash chain; verify detects an edited middle line, a deleted line, a truncated file |
| `broker` | every op; every refusal type reachable; `grant` or `manage` without prompt token → `not_model_callable`; every `manage` action applies only after confirmation and leaves the vault and grants byte-identical on decline; `manage` never creates a grant; `list` never shows another project; `policy` strings match `CONTRACT.md` verbatim; existence not disclosed in `request` responses |
| `merge` | the table of `REMOTE_SYNC.md` § 7.3 case by case (one side, both sides, identical change, delete vs edit both ways, tombstone expiry with an unchanged stale device); conflicts kept with the right winner; roots taken only from their own device; `revoked_at` sticky; hlc never decreases; property test: merging is deterministic and never loses a record (every input record is in the result or in `conflicts`) |
| `remote` | key derivations against fixed vectors; pairing code and confirmation code; key envelope sealed to the wrong device, with a forged issuer, a bad signature or a swapped AAD field never opens; recovery envelope; AAD checks (`account_id`, older `version` or `generation` → `remote_rollback`); padding to 4 KiB; a round against an in-memory fake server: 304, CAS conflict retried 3 times then `pending`, offline then catch-up; rekey accepted only from a non-revoked roster device; every user-only command refused with `not_model_callable` without a prompt backend and never printing the recovery key or a code on stdout, stderr or `--json`; conflicts (S.9b): a double edit on two devices lists one conflict on both, `resolve` swaps and syncs, `--keep current` drops it on both (it does not come back), refusals say nothing about the name; `history` lists labels and at most 10 versions; `restore` makes both devices equal to version N with fresh clocks, refuses an unknown version, an older generation and a tampered blob (hostile proxy), and a cancel changes nothing; anchors upload at most every 10 minutes (clock seam), `audit --verify` detects a rewritten log (`anchor_mismatch`) and a shorter one (`truncated`), prints `unavailable` with the server down and skips with `--offline`; conflict, history and restore output, the audit log and the server's data never hold a `TESTSECRET_` fixture |
| `server` (`internal/server`) | every endpoint's auth (missing, expired, revoked, wrong device, relayed signature with another origin); CAS on `version`; atomic `rekey` (all or nothing, revoked device's tokens dead); invite single use and expiry; pairing expiry and single use; recovery rate limits; size limits; logs contain no body, token or code; data directory files written atomically |
| `adapters` | golden files for each host config before/after; Gentle AI deny entries preserved; idempotency; uninstall restores byte-identical snapshot |
| `qbit-vault-pi` (vitest) | tool results never contain the fixture value; bash override pass-through for commands without references; input transform for each secret pattern; cancel drops input |

Fixture values all start with `TESTSECRET_` and end with a 24-char random suffix.

## Tier 2 — E2E in Docker (`bash e2e/docker-test.sh` for the sync battery)

Isolated images for Ubuntu (with and without Secret Service), Alpine (passphrase mode), and a Windows job in CI (native runner). Each runs:

1. `npx qbit-vault init` from the packed npm tarball; assert zero prompts with keychain, exactly one without.
2. `set` via stdin, `list`, `describe`, `exec` with a script that prints `$NAME` in every encoding the redactor knows and several it does not (hex, reversed) — the latter are expected leaks and are reported, not failed, to track R2.
3. Hooks: feed recorded Claude Code hook JSON to `hook pre-bash`/`post`; assert rewrites, denials and redactions.
4. MCP: drive `qbit-vault mcp` with a minimal MCP client; assert the four tools, their descriptions, the `policy` text as server `instructions`, refusal on `grant`.
5. Leaked directory: after storing fixtures in global and project layers, copy `$QBIT_VAULT_HOME`; assert no file except `audit.jsonl` contains any fixture value, secret name or project root (R-VAULT-09), and `audit.jsonl` contains no value.
6. `uninstall`: configs byte-identical to the pre-init snapshot.
7. **Sync** (`bash e2e/docker-test.sh`; compose project `qbv-e2e-sync`: one `qbit-vault-server`, a recording TLS proxy, client containers A, B and C and an auditor; prompts driven by the test prompt backend): register on A, join B by pairing (two live processes: `join` polls while `approve` runs, and the driver carries the confirmation code from A's transcript to B) and C by recovery; a secret set on A is listed on B and C and usable (after a grant; refused before it) on both; offline edits on A and B of the same record produce one winner (the later edit) and one conflict, seen identically on both; a project layer is listed as unlinked on B and its secret appears only after `link`; revoke C, then C gets `device_revoked` while A and B are on generation 2 and the new recovery key differs; the proxy replays an older recorded generation-2 `GET /v1/vault` and B exits 5 with `remote_rollback`, its `vault.enc` and `key.enc` byte-identical, then syncs again once the replay stops. Then the auditor scans the server's whole `/data` volume and every recorded exchange (URL, headers, request and response bodies) for every fixture value, secret name, project path, device label, passphrase, recovery key and confirmation code, raw and in base64, base64url, percent-encoded and JSON-escaped form: **any hit fails** (R-SYNC-02). A scanner self-check plants a needle in each encoding first, and a positive control scans A's own vault home, whose audit log names the secrets, so a scan that sees nothing cannot pass. The clients' vault homes are scanned for values, and every byte the driver captured from qbit-vault commands is searched for values and keys. The driver prints PASS or FAIL per check, exits non-zero on any failure and always runs `docker compose -p qbv-e2e-sync down -v` on exit.

   - **Test prompt backend.** The client image builds qbit-vault with `-tags e2eprompt`, which adds the `scripted` backend (`QBIT_VAULT_PROMPT=scripted`, `internal/prompt/scripted.go`). It answers from a file (`QBIT_VAULT_SCRIPTED_ANSWERS`, one line per prompt in the order asked, waiting up to `QBIT_VAULT_SCRIPTED_WAIT` for the driver to append the next one) and appends what it was asked and shown (including the recovery key and confirmation code) to `QBIT_VAULT_SCRIPTED_TRANSCRIPT`, never an answer. Passphrases never come from the queue: they are the first line of `QBIT_VAULT_SCRIPTED_PASSPHRASE_FILE`, so the vault runs in passphrase mode (there is no Secret Service in the container) and the driver need not know how often a command unlocks it. **Release builds do not contain it**: without the tag `scripted` is `ErrUnknownBackend`, and `go test ./internal/prompt` proves it three ways (the selector refuses the name, `go list` shows `scripted.go` only with the tag, and the compiled `cmd/qbit-vault` binary holds none of the backend's strings). Run `go test -tags e2eprompt ./internal/prompt` for the backend's own tests.
   - **Topology.** Clients reach the server only through the proxy, over `https://proxy:8443` with a throwaway CA passed as `--ca-file /certs/ca.pem`; the server's `QBV_SERVER_PUBLIC_URL` is that same origin. The proxy writes each exchange to a volume as `N.meta`, `N.req` and `N.resp`, and replays a recorded response when `control/replay` names it. The images are test images: never push them.
8. **Multi-field request**: a three-field request (two `text`, one `secret`) through the broker stores all three with one token and grants each; one blank field stores none.
9. **Host registration** (`bash e2e/hosts-test.sh`; compose project `qbv-e2e-hosts`, image target `hosts` of `e2e/Dockerfile`: the e2eprompt binary plus bash, jq and python3; the scenario is `e2e/hosts/scenario.sh`, run inside the one container): `HOME` is a fake user home holding the user's own `~/.claude.json` (another MCP server, unrelated keys, tab formatting), `~/.claude/settings.json` (own hooks, one named like a Gentle AI hook, deny and allow lists), `~/.codex/config.toml` (comments, another `[mcp_servers.x]`, CRLF) and `~/.pi/agent/mcp.json` (another server), with their sha256 saved; the image has no `claude`, `codex` or `pi` binary, so detection is by directory. Steps: `init --passphrase` registers the three hosts (exact host lines, the printed `pi install npm:qbit-vault-pi` line, doctor `healthy`), every config holds our entries and every user entry (jq), the TOML parses (`tomllib`) and keeps its CRLF; a second `init` and `sync` change nothing (sha256) and take no snapshot; `hook pre-bash` denies `qbit-vault set` and `qbit-vault remote join` and passes `ls`; after `set` and `unlock`, `hook post-bash` returns `updatedToolOutput` without the value, `post-read` redacts, `user-prompt` blocks without echoing, and after `lock` the hooks fail open with the `vault locked` warning; deleting our hook from `settings.json` makes `doctor` warn `run 'qbit-vault sync'` (exit 1), `sync` restores the file byte for byte and `doctor` is healthy; a later user key in `~/.claude.json`, then `uninstall` (answer `y`) restores the Codex and Pi files byte for byte, strips only our entry from the files the user edited and keeps the vault; `uninstall --purge` with a wrong word changes nothing and with `purge` deletes only the vault home. Last, every captured stdout and stderr, the transcript and every file under the fake `HOME` are searched for the `TESTSECRET_` value and the passphrase, after a planted-value self-check. The container never mounts a host directory and the binary never runs on the host; the script prints PASS or FAIL per check and `N passed, M failed`, exits non-zero on any failure and always runs `docker compose -p qbv-e2e-hosts down -v` on exit.

   - **Driving prompts.** As in item 7: the answers file is rewritten before each command (`y` for `uninstall`, `nope` then `purge` for the two `--purge` runs, the value for `set`), the passphrase comes from `QBIT_VAULT_SCRIPTED_PASSPHRASE_FILE` (`init --passphrase`, `unlock`), and `XDG_RUNTIME_DIR` points at a tmpfs directory (`/dev/shm/qbv-run`) so `unlock` has a cache the hooks can read.

## Tier 3 — cross-agent battery (`scripts/cross-agent-battery.sh`, out of CI)

Spawns real hosts in sandboxed HOMEs with a mock LLM provider that replays scripted tool calls:

- Pi / Gentle Shell: `gentle-shell --mode rpc` with the extension; script: request → capture (driven through RPC UI events) → bash with `$GITHUB_TOKEN` → read of a file containing the value.
- Claude Code: `claude -p` with hooks and MCP; script: Bash referencing the token before and after `secret_request`.
- Codex: `codex exec` with MCP.
- OpenCode: `opencode run` with MCP + plugin.

Costs real host sessions; run before merging anything touching exec/redact/prompt/mcp/hooks/extension.

## Manual smoke: native dialogs (once per OS, before a release)

The dialogs open on a real desktop and cannot run in CI; unit tests cover the command each backend builds. Use a throwaway `--home`, and type `TESTSECRET_manual` as the value.

1. **Windows 11, PowerShell 5.1.** `QBIT_VAULT_MANUAL_DIALOG=1 go test ./internal/prompt -run TestManualPowerShellDialog -v` opens a secret, a choice and a confirmation dialog. Check: the dialog is TopMost above other windows; the reason with quotes, `$` and a newline is shown as typed, with `\n` for the newline; the box is masked; Esc cancels (`cancelled`); `qbit-vault set NAME` opens the dialog and stores the value; `QBIT_VAULT_PROMPT=tty qbit-vault set NAME` asks in the terminal; from a service session, or with `powershell.exe` off `PATH`, the command ends with an unavailable error, not a hang.
2. **macOS.** `qbit-vault set NAME` shows the hidden-answer dialog with the request; Cancel ends `cancelled`; `qbit-vault grant NAME` shows the scope list; over `ssh` from a machine with no GUI app the terminal prompt is used.
3. **Linux, GNOME (zenity) and KDE (kdialog).** With `DISPLAY` or `WAYLAND_DISPLAY` set, `set` opens the dialog; on a console login (no display) the terminal prompt is used; `QBIT_VAULT_PROMPT=kdialog` on a machine without it fails with `prompt backend kdialog is unavailable`.
4. **Several fields.** A `secret_request` with a `text` and a `secret` field: PowerShell and zenity show one form (the text box visible, the secret box masked); osascript, kdialog and the terminal ask one box after the other with `field N of M`; Cancel on any box stores nothing.
5. **Every OS.** The value is stored (`exec` with a grant prints it redacted); nothing of the value is in the process list command lines while the dialog is open; a dialog left open ends with `prompt timed out` after `QBIT_VAULT_PROMPT_TIMEOUT` and the helper process is gone.

## Leak battery (every tier)

`exec` leak test (`TestExecLeakBattery`, `internal/cli`): a child prints its secret in raw, base64, base64url, percent, JSON-escaped and split-across-writes form on stdout and stderr; the test runs it in human, `--stream`, `--json` and `--json --stream` modes plus a dump attempt, then scans all captured output and every file under the vault home for the value in the raw, base64, base64url and percent encodings.

After each test, every byte that could reach a model is captured: tool results, MCP responses, hook stdout, host session files (`~/.pi/agent/sessions/**`, `~/.claude/projects/**`, Codex/OpenCode logs), qbit-vault's own stdout/stderr, the audit log, `backups/`, core dumps if any. The battery greps all of it for `TESTSECRET_` and for the base64/percent/JSON encodings of every fixture. **Any hit fails the run.** CI blocks merges on it; a PR touching the listed packages without adding a leak case is rejected by a path-based check.

In CI, `tools/leakgrep` (`go run ./tools/leakgrep PATH...`) runs over `ci-logs/`, which holds the verbose (`-v`) stdout and stderr of every `go test` run on each OS, so output printed by passing tests is scanned too. It scans recursively for `TESTSECRET_` raw, percent-encoded and JSON-escaped, and for base64 (standard and URL-safe) at all three byte alignments. It reports `path:offset: encoding` and never the surrounding bytes; any hit fails the job.

## Contract conformance (`internal/conformance`)

A host adapter is conformant when, against the JSON schema in `contracts/secrets-broker/v1/`:
- every request it emits validates;
- every response it accepts validates;
- it handles every refusal type (table in CONTRACT.md) with the documented behavior;
- a `grant` sent over its model-facing transport is refused.

`internal/conformance` loads the schema and validates a message as the `$def` of its op (`<op>Req`, `<op>Res`) or as `refusal`, using `github.com/google/jsonschema-go`. `TestContractConformance` (`internal/cli`) drives every op through `broker --op` against a real vault: success and refusal paths, its own requests validated too, and the schema's refusal `type` enum compared with the code's. Host adapters (phase 3) reuse the package against their own traffic.

## Property and fuzz targets

- `redact`: `FuzzRedactStream` — random values, random chunking, random surrounding bytes; invariant: output never contains the value in any modeled encoding.
- `internal/dumpguard`: `FuzzDumpGuard` — mutated known dump commands (prefixes, wrappers, quoting, subshells) must still be refused, and arbitrary text must never panic `Match`, `Segments` or `Binaries`. Every default pattern also has a positive and a negative case, and the embedded `default.yaml` must stay byte-identical to `defaults/dumpguard.yaml`.
- `vault`: `FuzzEnvelope` — corrupted envelopes never decrypt to anything, never panic.
- `remote`: `FuzzRemoteObject` — mutated remote vault objects, key envelopes and anchors are always refused, never panic, never partially applied.
- `merge`: `FuzzMerge` — random bases and edit sequences on two sides; invariants: deterministic, no record lost, tombstones respected.
