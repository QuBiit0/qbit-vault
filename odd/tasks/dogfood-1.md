## Log

- L1. User request: "Probarlo de verdad primero (Recomendado)". Real use 2026-11-05: `set` through the native dialog (an OK on an empty box is correctly refused as `empty value`), CLI exec refused without a grant, dump-guard refusal, once grant consumed, then Claude Code via MCP counted 9 characters without ever showing the value; every MCP grant has a matching `prompt` audit record (user-approved dialogs).
- L2. D1-D4 done by gentle-ai-worker (RED per task: `where bash` resolved to `System32\bash.exe`; the S6 command printed `printf: usage` and `0`; 14 allowed-case failures for D2; the once grant lost after a start failure over CLI and broker; 0 refusal records for the MCP session). S6 root cause: `planExec` joined the words after `--` with plain spaces, so `sh -c 'printf "%s" ... | wc -c'` reached the shell split apart; `joinCommand` now quotes a word that holds a blank for the effective shell (docs/CLI.md no longer says words are not re-quoted). S2: Git's installer puts only `Git\cmd` on PATH, so a bare `bash` fell to `cmd` and then to WSL; bare `bash`/`sh` now resolve outside System32/Sysnative/WindowsApps or to Git's `bin\`, Git's `bin` is prepended to the child PATH, and without Git the command is refused before any grant is claimed. D3: a once grant is claimed under the grants lock as before and released (`grants.Restore`) unless the child actually started; a child that starts and exits non-zero keeps it spent. D4: `broker.Auditor.Refused` appends `{"event":"refusal","session",...,"by":"agent","refusal","names"}` for every refusal on the broker/MCP path, names only.
- L3. Parent review: the worker followed the parent's own task text and allowed digest tools (`sha256sum`, `md5sum`, `cksum`, ...) as "counters". That was wrong: a digest of the value lets whoever reads it test guesses offline, so a weak secret falls to a dictionary. Digests are refused again (only `wc` counts); test `TestDigestOfTheValueIsADump` checks the POSIX matcher alone, because the existing refusal table passes a case when either matcher refuses and `MatchRaw` (no pipe model) refused digests vacuously (RED: 5 failures). CLI.md and PRD.md corrected.
- L4. Independent verification of the D1-D4 tree found two MAJOR dump-guard bypasses and one MINOR. MAJOR-1: `dropLengths` decided "inside a double-quoted string" with its own mini-scanner, which a nested `$('"')`, a nested `$("a$env:X.Length")`, a here-string or a typographic quote fooled, so a `$env:NAME.Length` that PowerShell expands to the value was rewritten to `0` and allowed. Now the rewrite happens only when the whole command holds no quote of any kind (ASCII, backtick, `‘ ’ ‚ ‛ “ ” „`), no `$(`, no `@`, no `{` `}`; anything else keeps `$env:NAME` and is refused (so `Write-Output "len: $($env:X.Length)"` is refused again). MAJOR-2: `countsOnly` accepted any `echo`/`printf` before a counter, so `printf '%d'`, `printf "$X"` (format string), several operands and `echo -e` could reach the pipe in forms that are not the plain bytes of one value; now only `printf %s OPERAND` and `echo [-n] OPERAND` with OPERAND exactly `$NAME`/`${NAME}` of an injected name. MINOR: `joinCommand` for pwsh now doubles `‘ ’ ‚ ‛` too (RED against a real `pwsh`: the verifier's `a ’; Write-Output INJECTED ; ‘ b` ran a second command). Tests assert each refusal with Match and MatchRaw on their own (producer shapes with Match, the matcher that models pipes). Documented as known `cmd` limits: a word with a blank that also holds `"` is left unquoted, and `%VAR%` inside quotes is still expanded by cmd. Open MINOR left as is (documented, not fixed): `grants.Restore` cannot tell a purge from a revoke, so a revoke or value replace that lands in the milliseconds between a once-grant claim and a start failure is undone.
- L5. Decision (parent): the D2 relaxation is withdrawn entirely. A second independent review of the tightened rules still found working bypasses confirmed with real shells on a fake value: PowerShell `Write-Host a$env:X.Length` prints `aTESTSECRET_probe123.Length` (a bareword argument expands `$env:X` but not `.Length`), and the counter-pipe exemption was a regression over the old guard (`set -x; echo $X | wc -c`, `wc(){ cat; }; ...`, a redefined `printf` all print the value). A guard that reads text cannot see how the shell will run it, so every new allowance is a new bypass class. `match.go` and `segments.go` are back to HEAD, `counters.go` is deleted, and `TestNoCounterOrLengthExemption` pins that the 12 shapes are refused (RED seen first) while `${#NAME}` stays allowed. The real dogfood problem (an agent wanting a length) is solved without loosening anything: the `secret_exec` description (CONTRACT.md and internal/mcp, kept equal by `TestDescriptionsMatchContract`) now says "to use only a length, write ${#NAME}". Kept from D1-D4: WSL avoidance, `joinCommand` quoting (incl. PowerShell typographic quotes), once grants released when the child never started, broker refusals audited. Open MINORs: `grants.Restore` cannot tell a purge from a revoke (a revoke in the milliseconds between a claim and a start failure is undone); cmd quoting limits documented; `echo${IFS}$X` and cmd `echo.%X%` are pre-existing guard gaps (redaction covers them).
