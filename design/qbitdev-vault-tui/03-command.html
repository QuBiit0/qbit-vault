qbit vault tui

by qbitdev · direction 03 · command

Command. A command-palette-first single list with fuzzy filter and inline detail, in the manner of k9s and fzf. Fastest for daily use; least discoverable on a first run, which is why first run is a checklist.

User flow

  1. First run: the checklist (vault, key, hosts) runs step by step and ends on Add a secret.
  2. Daily: open, type a few letters, enter. Everything is one fuzzy list; tab scopes it, > switches to actions.
  3. Revoke, repair and verify are keys on the row you are looking at; the row's detail line says what each will do.
  4. Errors replace the list with a message and the next action as the first row.

Reading the screens

A prompt line on top (›, the filter, the scope chip and the count), a grouped list, and a detail line under the selected row. Matched letters are underlined; the selected row has the blue→green gradient. Green is granted or healthy, amber a warning, flare an error. Values are never shown.

01 Guided first run (checklist palette)

DefaultChoiceLoadingDone First run is the same list the user will use every day: a checklist where each row is one step. The detail line says what the step will change before enter is pressed.

02 Home: one list for everything

Default No sections to navigate: secrets, grants, hosts and actions live in one grouped list. “Needs attention” floats problems to the top. Values are never rendered; the inline detail shows bullets.

03 Fuzzy filter

DefaultEmpty result Typing filters every kind at once; matched letters are underlined. Results keep their group, so a name that is a secret and a grant shows up twice with different meaning.

04 Actions and the masked add form

DefaultFormError Typing > turns the list into a command palette: configure, lock, restore, update. Choosing Add turns the row into an inline form whose value is masked.

05 Grants and revoke

DefaultRevokedEmpty Scoped with tab or by typing grants. Only revoke exists: the TUI has no grant action by design (invariant 6).

06 Hosts: drift and repair

DefaultRepaired Drift reads as a warning row with its cause; enter on it is the repair, and the detail says what repair will and will not touch.

07 Audit

DefaultVerifiedChain broken The hash-chained log as a filterable list: type a name or an event. Refusals are the only rows in flare.

08 Sync status

DefaultLoadingOffline The server, each device and each conflict are rows. Pairing codes and recovery keys never show in the TUI: those actions open a native dialog.

09 Update (planned)

Planned Rows, not a special page. The copy says it does not exist yet.

10 Empty, locked, error

EmptyLockedError Same list, same keys: the state is a short message plus the next action as a row.
