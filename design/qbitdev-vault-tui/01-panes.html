qbit vault tui

by qbitdev · direction 01 · panes

Panes. A lazygit-style dashboard: everything on one screen, driven by the keyboard, with the key hints always in the footer. Built for people who live in the TUI and want state at a glance.

User flow

  1. First run: Setup (keychain, hosts) → lands on Secrets, empty, with the first action named.
  2. Daily: an agent asks, a native dialog approves; the user opens the TUI to see grants, revoke, check audit, repair hosts.
  3. Exits: esc goes back one level, q quits; every destructive key asks or snapshots first.
  4. Errors: lock, missing key, broken audit chain and offline sync are screens with a next action, not stack traces.

Reading the screens

Sections on the left (1–7 jump), list in the middle, detail on the right; the focused pane has the blue border. Green is granted or healthy, flare refused or error, amber a warning. The gradient only marks the selected row. Values are never shown anywhere in this direction.

01 First-run setup

DefaultLoading (step 4) Opens when no vault exists. Three decisions, each with its consequence stated; nothing is written until Apply.

02 Secrets (home)

Default Three panes: sections, list, detail. Values are never rendered: the detail shows bullets and the words “never shown”. Project secrets of the current repository (shop-api) sit next to global ones.

03 Add a secret (masked field)

FormError (blank value) A modal over the dimmed panes. The value field is masked and only reveals its length. Blank input fails without writing anything and keeps the other fields.

04 Grants and revoke

DefaultSuccess toastEmpty Read and revoke only. Grants come from the native dialog an agent triggers (security invariant 6), so there is no grant key here. Revoke has no confirmation by design and takes effect for the next check.

05 Hosts: drift and repair

DefaultRepaired The state of each host is the doctor report, per step. Drift is named, the repair plan is listed before anything runs, and a snapshot is always taken.

06 Audit

DefaultVerifiedChain broken A read-only view of the hash-chained log with the same filters as `qbit-vault audit`. Refusals read in flare, never as a bare error. Verify reports success or the exact line that breaks.

07 Sync status

DefaultLoadingOffline Server, devices, conflicts and history in one place. The server is untrusted, so the screen says what it sees (sealed data) and every key or code step hands off to a native dialog.

08 Doctor

Default The read-only health report as a list, one line per check with the same names as `qbit-vault doctor`. Enter jumps to the section that owns the problem.

09 Update (planned)

Planned Self-update needs published releases (Phase 5). The screen exists so the layout is settled, and says so in copy. Keys are shown disabled, not hidden.

10 Empty, locked, error

EmptyLockedError Every non-happy state names the cause, says what is safe, and offers the next action. Locked asks for the passphrase in a masked field; the key error never prints a value and offers recovery paths.
