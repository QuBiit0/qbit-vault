qbit vault tui

by qbitdev · direction 02 · launcher

Launcher. A centered menu in the manner of the gentle-ai and engram installers: a splash, a guided wizard one question at a time, then a menu of actions. Gentlest for first use; slower for experts.

User flow

  1. First run: Splash → Setup wizard (vault, keychain, agents, apply) → Done offers to add a secret.
  2. Every later run: Main menu. Pick an area, do one thing, esc returns to the menu.
  3. Actions are menu items with consequences in their hint (“snapshot first”, “asks first”), so nothing is a surprise.
  4. Errors and empty states are screens with a menu of next actions.

Reading the screens

One column, one decision at a time; the selected row carries the blue→green gradient. Crumbs on top (Menu › Secrets), keys at the bottom. Green is granted or healthy, amber a warning, flare an error. Values are never shown: the value column is bullets and the add form is masked.

01 Splash and first run

Default Plain qbit-vault with no vault yet. The full mark with orbits, one sentence of promise, one primary key.

02 Guided setup wizard

DefaultLoading (apply)Done One decision per screen, the step trail on top, the consequence in plain words, one recommended default pre-selected. Nothing is written until Apply.

03 Main menu

Default The launcher. Each entry carries a live one-line summary so the menu is also the dashboard; warnings are amber, never red unless something failed.

04 Secrets and actions

Default A plain list: names, layers, a masked value column that is always bullets, the grant state. Enter opens the actions for the row, so the list stays a list.

05 Add a secret (masked)

FormError A single-column form. The value is a masked field that only shows its length; a blank value fails loudly and keeps what you typed.

06 Grants and revoke

DefaultRevokedEmpty View and revoke. There is deliberately no grant action in the TUI (security invariant 6): grants exist only through the native dialog.

07 Hosts: drift and repair

DefaultRepaired Drift is stated with its file and step; the repair is the first menu item, and says it snapshots first.

08 Audit

DefaultVerifiedChain broken Newest first, the same filters as `qbit-vault audit`. Commands, reasons and values are never stored, so none can appear here.

09 Sync status

DefaultLoadingOffline Remote sync is opt-in. Pairing codes and recovery keys never appear in the TUI: those items open a native dialog.

10 Settings (configure)

Default The configuration the user asked for in S5: keychain mode, prompt backend, update check, sync, backups, uninstall. The update check is shown as planned.

11 Update (planned)

Planned Layout settled now; the copy says it does not exist yet. The disabled action stays visible so the future shape is clear.

12 Empty, locked, error

EmptyLockedError Every state names the cause, says what is safe, and offers the next action as a menu item.
