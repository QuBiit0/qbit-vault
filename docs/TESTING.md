# Testing

Three tiers plus a leak battery that runs on every tier. **Built today:** Tier 1 (`go test ./...`, run in CI on Linux, macOS and Windows with `tools/leakgrep` over the verbose output; see § CI below), the Docker sync battery (`e2e/docker-test.sh`) and the Docker hosts battery (`e2e/hosts-test.sh`), the Docker install-from-scratch battery (`e2e/install-test.sh`), the leak battery and the conformance harness. **Planned:** the rest of Tier 2 as separate images (items marked *planned* below), Tier 3, `qbit-vault-pi` tests (Phase 4) and a Windows/macOS e2e job. Package names below are the directories under `internal/`.

## Leak battery (every tier)

`exec` leak test (`TestExecLeakBattery`, `internal/cli`): a child prints its secret in raw, base64, base64url, percent, JSON-escaped and split-across-writes form on stdout and stderr; the test runs it in human, `--stream`, `--json` and `--json --stream` modes plus a dump attempt, then scans all captured output and every file under the vault home for the value in the raw, base64, base64url, percent and UTF-16 (LE and BE) encodings; the battery also runs a child that writes the value as UTF-16LE (`TestExecRedactsUTF16Output`), and the post-read hook redacts a file written that way (`TestHookPostReadRedactsUTF16`).

`TestExportImportLeakBattery` (`internal/cli`) does the same for the backup path: `export` (done, refused, forced, with a short passphrase, human and `--json`) and `import --from-export` (wrong passphrase, success in human and `--json`) are captured, and stdout, stderr, both audit logs, the export file and every file under both vault homes are scanned for the fixtures and for the export passphrase.

After each test, every byte that could reach a model is captured: tool results, MCP responses, hook stdout, host session files (`~/.pi/agent/sessions/**`, `~/.claude/projects/**`, Codex/OpenCode logs), qbit-vault's own stdout/stderr, the audit log, `backups/`, core dumps if any. The battery greps all of it for `TESTSECRET_` and for the base64/percent/JSON encodings of every fixture. **Any hit fails the run.** CI blocks merges on it; a PR touching the listed packages without adding a leak case is rejected by a path-based check.

In CI, `tools/leakgrep` (`go run ./tools/leakgrep PATH...`) runs over `ci-logs/`, which holds the verbose (`-v`) stdout and stderr of every `go test` run on each OS, so output printed by passing tests is scanned too. It scans recursively for `TESTSECRET_` raw, percent-encoded and JSON-escaped, and for base64 (standard and URL-safe) at all three byte alignments. It reports `path:offset: encoding` and never the surrounding bytes; any hit fails the job.

## Contract conformance (`internal/conformance`)

A host adapter is conformant when, against the JSON schema in `contracts/secrets-broker/v1/`:
- every request it emits validates;
- every response it accepts validates;
- it handles every refusal type (table in CONTRACT.md) with the documented behavior;
- a `grant` sent over its model-facing transport is refused.

`internal/conformance` loads the schema and validates a message as the `$def` of its op (`<op>Req`, `<op>Res`) or as `refusal`, using `github.com/google/jsonschema-go`. `TestContractConformance` (`internal/cli`) drives every op through `broker --op` against a real vault: success and refusal paths, its own requests validated too, and the schema's refusal `type` enum compared with the code's. The host adapters write no contract traffic of their own; the package is for a future host that does (the Pi extension).

## Property and fuzz targets

- `redact`: `FuzzRedactStream` — random values, random chunking, random surrounding bytes; invariant: output never contains the value in any modeled encoding.
- `internal/dumpguard`: `FuzzDumpGuard` — mutated known dump commands (prefixes, wrappers, quoting, subshells) must still be refused, and arbitrary text must never panic `Match`, `Segments` or `Binaries`. Every default pattern also has a positive and a negative case, and the embedded `default.yaml` must stay byte-identical to `defaults/dumpguard.yaml`.
- `vault`: `FuzzEnvelope` — corrupted envelopes never decrypt to anything, never panic.
- `remote`: `FuzzOpen` — mutated remote vault objects, key envelopes and anchors are always refused, never panic, never partially applied.
- `merge`: `FuzzMerge` — random bases and edit sequences on two sides; invariants: deterministic, no record lost, tombstones respected.
